## Быстрая настройка

Закройте Safari (⌘Q). [Прочитайте код](../fix.command) и [скачайте fix.command](https://github.com/Degisik/bitwarden_biometric-popup-fix/raw/refs/heads/main/fix.command) в «Загрузки». Нужен Swift от Apple; если его нет, выполните `xcode-select --install`. Только для одного аккаунта и стандартной Связки ключей.

Сначала только проверка:

```sh
cd ~/Downloads
bash fix.command
```

Если предварительный просмотр добавляет только компонент Safari к настольному приложению:

```sh
bash fix.command --apply
```

Подтверждайте только в окне macOS. После `save_acl=0` откройте Safari и проверьте Touch ID. Скрипт — читаемый текст, без сети, `sudo` и чтения секрета. Только `--apply` сохраняет разрешение. При неожиданном результате остановитесь. [Подробности и целостность](../README.md#quick-setup).

---

Здесь описан способ, который помог на одном Mac: Touch ID работал в настольном Bitwarden, а Safari постоянно запрашивал доступ к `Bitwarden_biometric`. Пользователь подтвердил результат на macOS/Safari 26.5.2 и Bitwarden 2026.8.0. Это не официальное исправление и не универсальное решение.

В списке разрешённых приложений было настольное приложение, но отсутствовало `/Applications/Bitwarden.app/Contents/PlugIns/safari.appex`. Добавили только этот подписанный компонент, сохранив остальные разрешения. Это постоянный доступ к конфиденциальному элементу. Код не читает и не меняет секрет и не разрешает доступ всем приложениям.

Пользователю не удалось выбрать компонент внутри пакета `.app` через графическое окно выбора. Поэтому такой путь не заявлен как проверенный.

1. Завершите Safari через ⌘Q и сохраните обычный доступ по мастер-паролю.
2. Выполните [проверки инструментов Swift от Apple и подписи](../README.md#before-running). При необходимости используйте только инструменты Apple.
3. Прочитайте [весь код и создайте локальный файл](../README.md#review-and-create-the-local-source). Код не загружается из сети; используйте тот же сеанс Терминала.
4. Запустите без `--apply`. Ожидается `Dry run; unchanged`, а в исходном списке — только настольное приложение. При нескольких совпадающих элементах, аккаунтах, нестандартной связке ключей или неожиданных разрешениях остановитесь.
5. Если согласны с изменением, запустите с `--apply`. Пароль Mac/Связки ключей вводите только в системное окно macOS. `sudo` не нужен. Если авторизация не проходит, остановитесь.
6. После `save_acl=0` повторите запуск без `--apply`: должны появиться оба пути и `Already present; no changes`. Перезапустите Safari и несколько раз проверьте блокировку и разблокировку.

Для отмены откройте Связку ключей → нужный элемент → Управление доступом и удалите только добавленную запись с путём `safari.appex`, оставив настольное приложение. Этот графический способ отмены здесь не проверялся. Если записи нельзя различить, обратитесь в поддержку Bitwarden, не удаляя сам элемент. Не публикуйте пароли или дампы Связки ключей. Перевод выполнен с помощью ИИ и не прошёл независимую проверку носителем языка; технический оригинал — английский.
